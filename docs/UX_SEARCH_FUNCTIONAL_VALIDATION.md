## 修复内容与原因

1. **纠正模型能力假设。** 当前 [DeepSeek Responses 官方说明](https://api-docs.deepseek.com/guides/responses_api/) 明确忽略 `web_search` 等内建工具。兼容 Responses 的请求格式不等于提供内建搜索。此前报告的支持判断由此更正。精确匹配官方 DeepSeek 主机后，旧的原生搜索选择兼容路由到独立网页搜索，并保留可见的选择原因；不改原模型、密钥或用户数据库。未知兼容供应商不会被一并宣称不支持。
2. **复用已有搜索接口接普通网页搜索。** 使用现有 `SearchProvider`、安全 HTTP、来源存储和抓取/引用链，不新造搜索平台。已有明确 SearXNG 配置保持优先；未配置时可使用普通网页搜索。早期接 Bing 的多次真实任务仍偏题；最新免费对照表明 DuckDuckGo 正常 HTML 首屏返回相关结果，现改接该入口，不需要模型搜索密钥。HTML 只解析普通结果，不执行脚本，不把广告、验证码、HTTP 200 或空页面当成功来源。
3. **遵循实际系统代理。** 本机已配置 Windows 静态代理 `127.0.0.1:7890`，原客户端却强制直连。新实现遵循环境配置优先和 Windows 静态配置；代理 CONNECT 目标仍是已校验的公网 IP，TLS 校验原网站主机，每次跳转重新核对原任务网络权限。代理失败不隐式退回直连，不改系统代理设置。
4. **传入当前日期。** 原真实模型请求没有运行时日期，模型自行用了 2025 年查询。“最新”现在有明确的运行时 UTC 日期参考，日期不是事件真实性的证据，仍需读取来源核实。
5. **修复执行后的提前结束。** 首次普通 Thread 中模型工具调用后返回结构化 `continue`，说要继续精确查询，却被当成最终答复消费了输入。已增加精确 Thread 绑定的单次有界纠正，并保留 `finish` 仅结束回复、`wait` 等待实际输入和原预算限制；定向回归通过，仍须真实任务验收。
6. **禁止静默丢弃伪工具调用。** 第二次普通 Thread 返回根 JSON 后附 DSML 调用标记，但供应商实际 `tool_calls` 为空。旧尾随文字容错把这些标记丢弃后接受了根答复。已修复精确识别和原一次纠正；第三次真实验收证明再次仅文字 continue 会被拒绝。不会执行这些文字或假造结果，普通消息里讨论工具格式不受影响。
7. **修正 DeepSeek 工具阶段输出格式兼容。** 第三次失败后只进行一次单变量对照：同真实请求的 input、tools、model、advanced、stream 和输出上限，仅去掉 `text.format=json_object`；供应商返回 2 个真实原生搜索调用，未执行这些调用。生产修正限定 HTTPS 官方 `api.deepseek.com` 默认端口的有 function tools 阶段，无工具时仍使用原生 JSON，最终根 JSON 校验不变。其他供应商不扩大处理。当前官方文档未声明该组合互斥，此为实测兼容处理，不宣称一条对照证明普遍失败率。
8. **修复无项目对话的历史工具入口。** 第四次真实工具调用是 `history_search`。无项目 Thread 合法使用空 WorkspaceID，上层已提供该工具，入口却以非空项目 ID 为硬条件而报内部错误，留下 pending 调用。已去掉不一致的非空条件，仍核同 Run、Session、Thread 与任务身份，不扩大读取范围。主提示同时明确应用提供的实际网页 function 名称，不以供应商有无内建搜索推断这些工具是否存在。

9. **让来源答复真正建立引用。** 第七次任务已完成相关搜索与原文读取，自然给出答复，但提示原先只说引用工具“可以”引用，模型直接贴网址，未建立引用记录。现明确在结束来源答复前调用现有 `web_citation`，论断必须有实际已读文字支持，返回链接贴在相应论断旁；引用未完成可使用原调度边界继续，不增加调用次数或另造引用。内部“非授权数据”仅指不能作为工具指令，不应对用户解释成“未经授权的来源”。第八个普通任务已遇到下述本地上下文阻断，引用流程仍未完成。

10. **避免搜索资料挤满本地上下文。** 搜索仅在模型视图精简重复元数据，保留全部来源ID/URL/rank和有界标题/摘要；提供带原SHA的现有history_read回读参数。来源资格不能从投影升格，已认证原生引用/未知结果形状不做此精简。网页正文保留原2048 Unicode字上限，并额外受同估算器2048 token约束；中文被进一步分成小页，next_offset按实际字符数计算。原工具记录、网页全文、Run权限和32K窗口均不改。真实失败截面和SQLite整SHA回读用于离线验收，仍须真实最终答复。

12. **给历史执行段证据真正分配上下文预算。** 原上限16Ki Unicode字符不是token上限，而且重复携带metadata和result；普通历史压缩后这块仍原样追加。现改为包含最终来源包装/消息开销的2048估算token预算，当前执行段原生工具配对不变。优先保最近回执、引用与各快照最近实际可见cursor，余量保短事实摘录；内容省略时明确告知并提供原SHA约束的既有history_read入口。不能截断身份或伪装完整claim。复核发现history_search/read包装自身不支持原件回读，因此不伪造可读入口；不扩大store读取范围。移动结果的destination_path等完整路径保留，内部执行结果省略时不能由外层completed推断成功。6顶层race22.090秒、vet、真实SQLite原件SHA回读及续读回归通过，最终3文件freeze SHA29e75b0c3ee578a77d0c133bb4589c56ef76dbe28e521269a35c41d8ea9b1cdf。
