## 用户目标

用户可以在一个任务中回答：这次改了哪些文件，当前实际代码在哪里，哪些检查验证了哪个版本，哪些已经失效；随后明确选择提交内容、分支与远端，创建或找到对应 PR，读取当前 CI 与审阅意见，再回同一任务修改。

## 取舍

- 默认任务级总览，历史执行仍可查看。任务事实与工作区其他改动分开，不能将整个脏工作树归为 Agent 成果。
- 复用现有 Thread/编辑/Host/检查点/交付记录聚合，不增加通用交付账本。没有代码版本绑定的旧检查显示无法确认，不能补造绑定。
- 复用成熟 Git CLI 和已有 typed Git / GitHub 服务、系统凭据与操作身份。先修预览/实际内容、linked worktree、精确 push 和未知结果问题，再接 UI。
- 首批 GitHub.com；创建默认草稿 PR。已有 PR 则直接进入，明确显示当前 head 的 CI/评论和刷新时间。自动合并与其他托管平台不在本批。
- 所有未知结果先只读核对原操作，不重复提交/推送/创建。实际远端写必须针对用户选择的对象；本项目既有未提交改动不是测试发布材料。

## 必须通过的验收

1. 多个后继执行、同路径连续修改、未应用提案、来源目录与隔离目录、非 Git、任务外修改、有界分页都能准确呈现。
2. 未提交文件变化也属于版本；旧测试结果须区分当前、过期、未绑定及无法读取。
3. 分支/worktree与选定文件提交真实执行，预览内容与提交相同，无关已暂存修改保持；状态漂移拒绝旧预览。
4. 推送只针对已确认的提交与远端，仅允许快进。内部使用精确远端 OID 的 force-with-lease 做条件更新，不提供历史重写；未知提交/推送结果只读核对。
5. 按仓库与分支发现已有 PR；创建草稿、PR/CI/评论真实刷新、远端 head 漂移、权限/离线/限流/部分数据、未知创建恢复均有证据。
6. 文件/行段及 PR 评论或失败检查可带来源返回当前对话，保留草稿；修复后可再次审阅和推送刷新。
7. 定向回归、真实隔离 Git/浏览器操作及最终包校验。协议夹具不冒充真实 GitHub 远端发布，Windows 原生验收继续单列。
