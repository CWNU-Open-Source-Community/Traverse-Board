## 实际改变

1. 普通 Thread 的模型可调用 `history_search` 和 `history_read`。前者按字面关键词搜索原消息和已记录终态的工具调用，空关键词可浏览；后者按来源 ID 读取原消息，或同一工具的原参数和结果。范围由 Go 当前 Thread、合法前驱 Run/Session、Workspace 和执行租约确定，模型不能在参数里指定其他对话。
2. 包括已经压缩的消息。这里的原文指数据库已保存、已脱敏的原始记录。保留原消息 ID、角色、来源、原文哈希以及工具 call ID、attempt、状态、参数/结果哈希；读取过去的结果不执行过去的工具，也不证明工作区今天仍是相同状态。来源字段如需脱敏，另保留其哈希并明确标记。
3. 摘要计算移到数据库写事务之外。先取来源快照，计算候选，再检查原消息集合（包括保留的尾部）、摘要、checkpoint 和 lease/generation，最后在一个事务内保存摘要并标记压缩。陈旧候选不能覆盖更新的输入。提取策略有小范围可替换接口，不能伪造来源或权限。
4. 搜索分页固定消息、工具及已落库结果事件的水位；已有 pending 工具后来完成，不会插入旧分页。回读工具自身的结果仍保存在执行账本，但不再次追加成摘要工具事实，避免重复放大历史内容。
5. 精确原文通过完整路径保持：保存回读结果时，在同一事务内按原请求重建来源投影并逐字比较。只保护验证过的正文，其他字段和其他工具继续脱敏。模型路由层用不可由 JSON 设置、且绑定内容哈希的内部标记保留这些已验证片段，避免多次对序列化 JSON 脱敏改坏原文及字节分页。
6. 对话活动显示“搜索对话历史”“读取历史原文”，沿用现有搜索/读取分组。没有增加常驻输入框按钮，没有把回读呈现成重新执行工作区工具。

没有引入新数据库、向量服务、Python/Node 记忆服务或模型代理。采用成熟实现强调的“原历史持久保留、模型窗口只是有界投影、需要时精确回读”的思路；不是移植 Codex 完整 runtime，也不是已经接入生成式摘要。

## 仍然明确保留的边界

- 默认仍是 4,000 字符/最多 12 条记录的规则摘录，不是语义无损摘要。改善在于遗漏内容可回读；是否选择恰当关键词、及时调用回读，仍取决于模型。
- 搜索是区分大小写的字面子串检索，支持中文，不是向量/语义搜索或分词全文引擎。每次最多扫描 256 条、返回 20 条；空结果但 `has_more=true` 时必须继续翻页。原文默认每页 4 KiB，最大 8 KiB，偏移为 UTF-8 字节；工具参数/结果分页片段不能当成完整 JSON。
- 原有每轮最多 4 个工具回合及任务预算继续生效。不能据夹具通过宣称任意长度原文都能在一轮内全部读完。
- 多个后继摘要累计的 16 KiB 保护上限尚未替换成有界滚动引用方案；没有静默删旧摘要或简单调高上限。
- 没有部署长期项目记忆后端，也没有证明真实模型在复杂自主编程任务上的成功率提高多少。固定协议 Provider 的验收证明接线、隔离、恢复和字节一致性。
- 原生窗口、物理剪贴板、IME、高 DPI 等旧未验事项，本批不作新声明。
