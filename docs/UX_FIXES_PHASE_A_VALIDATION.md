## 真实流程证据

证据目录：`<workspace>/output/playwright/ux-validation/`。全部使用隔离的 `CYBERAGENT_HOME`，真实 Go API 和 `web/dist`；模型响应来自本机确定性 OpenAI 兼容夹具，没有调用付费模型。

1. 空实例先写草稿，进入设置再返回，草稿保留；Web 按界面说明在服务端运行 `workspace init ux-fixture`，刷新后可发送。见 `01-empty-web-guidance.png`。
2. 默认路由创建并启动首轮，在夹具完成前就进入任务。见 `02-first-turn-before-completion.png`。
3. 补充消息收到明确排队状态；切换设置后保留独立草稿和停止入口；停止后实际连接被取消，排队消息的持久状态为 cancelled。见 `03-queue-reopen.png`、`04-stopped.png`、`stopped-transcript.json`、`provider-events.log`。
4. 停止后可以明确发送新消息继续；长回答上翻阅读与返回位置通过。见 `05-continue-running.png`、`06-reader-position-preserved.png`、`06-scroll.js`。
5. 390×844 的发送按钮边界为 x=341、y=773.5、28×28；停止为 x=266、y=42、72×31，均在视口内并实际点击。最小检查视口 390×480 下发送 y=409.5，未裁切。见 `07-narrow-sidebar.png`、`08-narrow-controls.png`、`09-narrow-interrupted.png`、`layout-*.png`。
6. 停止后刷新并重新连接，能看到上次中断提示。见 `10-interruption-after-reconnect.png`。
7. 显式模型 `openai/ux-scripted-model`，先完成首条，再消费下一轮输入。最终两个用户输入、两次模型结果、idle、队列 0。原请求最终 steering=committed，补充请求最初为 pending。见 `explicit-queue-result.log`、`explicit-queue-durable-final.json`、`11-explicit-queued.png`、`12-explicit-complete.png`。一次本机观测中，发送后 44 ms 出现执行控制；这不是性能预算或竞品基准。
8. 已受理且仍在运行时刷新页面，再连接同一实例，仍只有一个对应 Thread；执行状态为 idle、last_turn_interrupted=true，没有重复启动首轮。见 `disconnect-result.log`、`disconnect-final-state.json` 和 `13-disconnect-recovered.png`。未提交草稿跨刷新持久化不在本批承诺内。

执行中最初的人工走查用暂停夹具保留现场，触发过模型的 60 秒空闲重试；这不是正常模型时延数据。排队验收也捕捉到一次真实的 `ERR_EMPTY_RESPONSE`，原因是普通 HTTP 写超时。最终修复后重新演练超过 30 秒的请求成功，不能把失败尝试当成最终通过证据。

浏览器控制台中的主动停止 HTTP 499 与测试服务重启期间断连有明确来源，不能据此宣称控制台始终零错误。具体过程保存在本批日志和脚本中。
